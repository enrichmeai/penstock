## Security fixes from the v0.5.0 image scan

v0.5.1 is a patch release with no new features and no breaking changes. It applies the fixes the
v0.5.0 image scan listed for the application's own libraries and for the Gradle distribution the image
carries (#120). Three Spring Framework criticals remain, and the section on what is not fixed says why.

### In the application jar (#121)

Each library is now at or above the fixed version the v0.5.0 scan listed:

| Library | v0.5.0 | v0.5.1 | v0.5.0 findings it addresses |
|---|---|---|---|
| Tomcat | 10.1.55 | 10.1.60 | three criticals: CVE-2026-65182, CVE-2026-65905, CVE-2026-68525 |
| Netty | 4.1.135 | 4.1.139 | CVE-2026-75595 (critical), and five highs in the codec modules |
| Jackson | 2.21.4 | 2.21.7 | five highs in jackson-core and jackson-databind |
| PostgreSQL driver | 42.7.11 | 42.7.14 | CVE-2026-54291 (high) |

### In the image's Gradle (#122, #126)

The image carries a Gradle distribution so the agent can build the code it edits, and it carries it
twice: as `/opt/gradle`, and as the wrapper's copy in the seeded Gradle home. Both move from 8.14.5 to
**8.14.6**, which ships these versions:

| Library | 8.14.5 | 8.14.6 | v0.5.0 findings it addresses |
|---|---|---|---|
| BouncyCastle (bcprov) | 1.84 | 1.85 | CVE-2026-8763 (critical), CVE-2026-13506 (high) |
| Jackson | 2.18.6 | 2.18.11 | the Jackson highs listed against the Gradle distribution |
| jsoup | 1.15.3 | 1.23.2 | CVE-2026-75140 (high) |
| plexus-utils | 3.5.1 | 3.6.1 | CVE-2025-67030 (high) |

The in-container `gradle` stays on 8.x, so workspaces the agent builds see no version jump.

The Trivy report attached to this release shows the result. Read its `Total:` lines, not counts of
table rows.

### What is not fixed in this release

The v0.5.1 report (attached) totals 18 findings, against 61 in v0.5.0.

The report lists each Spring CVE once in `app/agent.jar` and once in the seeded Gradle cache, for each
package it affects. CVE-2026-47890 affects two packages, so 3 CVEs make its 8 critical rows. All 18
findings are below.

- **CVE-2026-47884 (critical), in Spring Web MVC's `XsltView`.** Its only listed fix is Spring
  Framework 7, which needs Spring Boot 4.
  [ADR 0004](https://github.com/enrichmeai/penstock/blob/v0.5.1/docs/adr/0004-spring-framework-7.md)
  records the decision (#124): Penstock stays on Spring Boot 3.5 for now, because the CVE is reachable
  only through an XSLT view and Penstock renders none. The move to Boot 4 is planned as its own
  project. `XsltViewGuardTest` (#125) fails the build if any of Penstock's classes or resources names
  Spring's XSLT view package, or if an XSLT view or resolver bean appears in the application context.
- **CVE-2026-47890 and CVE-2026-47892 (critical), not in the v0.5.0 report.** The report titles them
  "Stream corruption in Server-Sent Events (SSE) with view…" (spring-webmvc and spring-webflux) and
  "Header Predicate Bypass in WebFlux Functional Endpoints" (spring-webflux). Both list a fix only in
  Spring Framework 7. Penstock defines no WebFlux functional endpoints (it uses WebFlux only as an HTTP
  client), and it streams over SSE without rendering views. Whether either is reachable has not yet been
  confirmed against the full advisories; that check, and whether it brings the Boot 4 move forward, is
  tracked in #128.
- **Jackson 2.21.4 in the seeded Gradle home** (five highs: CVE-2026-89407, CVE-2026-89425,
  CVE-2026-68497, CVE-2026-91776, CVE-2026-91777). This is a cached copy used only to build; the
  application jar carries Jackson 2.21.7. It will be handled with the httpcore5 copies below.
- **httpcore5 in the seeded Gradle home** (CVE-2026-54399, CVE-2026-54428, high): 5.3.6 from the
  Spring Boot Gradle plugin, and 5.0.2 shaded inside Testcontainers' docker-java transport. Both are
  used only to build and test, neither is in the application jar, and they will be handled separately from
  this release, together with the Jackson copy.
- **CVE-2026-84782 (libssl3, high) in the Ubuntu base image.** Still present in this image
  (3.0.2-0ubuntu1.29); the fix, 3.0.2-0ubuntu1.30, comes with a refreshed base image.
