## Recall tells the model how to cite your memory, and what it may write

v0.5.2 changes one thing: the "Owner's memory" block Penstock puts in front of the model. It reaches web and IDE turns when memory is on (`AGENT_MEMORY_ENABLED=true`; it is off by default there), and Claude Code or Claude Desktop through the MCP `recall` tool, where memory is on by default (#132, #133). There are no dependency or Dockerfile changes since v0.5.1, and no breaking changes.

### What the block now says

The block's header keeps "apply them, do not redesign, and say when you depart from one". Whenever cards were loaded, it also gives the model two rules:

- **Cite the record.** When the model states a plan, it ends each decision with `[card: <id>]`, using only an id shown in the block, or with `[assumption] — ask:` followed by a question the owner could answer. These are the markers the planning contract (#92) specifies. A decision you can check in one hop names its card, and an unstated assumption becomes a question you answer once.
- **Propose, never write, beliefs.** The model never writes or edits a fact card. When work ends, or something is learned or corrected, it proposes one episode for your review: through `draft_episode` where it has that tool, otherwise as YAML in the episode shape, with each new belief as its own line under `learned`. Facts still come only from `consolidate.sh` and your review, because a fact's provenance must quote an existing episode.

The rules are neutral: they name no owner, project or domain. Your own wording still belongs in your `AGENT_LLM_SYSTEM_PROMPT`; the stock system prompt is unchanged. The header grows from 159 to 686 characters. It counts against the block's 12,000-character budget on every turn with memory, so 527 fewer characters are left for cards, and patterns are the first to be dropped when the block is full.

### What does not change

- With memory off, nothing is added to the prompt.
- `check-plan.sh`, which will check those markers, is not built yet (#92). Until it is, the markers are read by you, not by a script.
- Security: the image is rebuilt on its floating base image (`eclipse-temurin:21-jdk-jammy`) with current OS packages, so its scan can differ from v0.5.1's. The Trivy report attached to this release is the record for this image. The v0.5.1 notes say which findings are open and why (#128, #131).

### Breaking changes

None.
