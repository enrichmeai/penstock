## Penstock runs inside your IDE

Penstock now speaks the [Agent Client Protocol](https://github.com/agentclientprotocol/agent-client-protocol)
(ACP), so JetBrains Air and Zed can run it as their coding agent, next to the
vendor agents, on your own data.

```bash
java -jar penstock-0.3.0.jar --acp
```

Register that command in Air's `acp.json` or Zed's `agent_servers` — the exact
snippets, what the permission prompt means and the "nothing happens"
troubleshooting case are in
[Penstock in JetBrains Air and Zed](https://github.com/enrichmeai/penstock/blob/v0.3.0/docs/ide-agents.md).

**How it behaves in the editor**

- `read_file`, `list_dir`, `glob`, `grep` and `pod` reads run unprompted.
  `write_file`, `edit_file`, `shell`, `git` and `pod` writes each go through
  the editor's own permission prompt (`session/request_permission`: allow
  once, always allow, reject, always reject; "always" lasts for the session).
  `shell` and `git` are gated no matter how the agent is configured.
- The editor's working directory must be Penstock's configured workspace
  (`AGENT_WORKSPACE`); any other `cwd` is refused at `session/new`.
- ACP mode runs with in-memory storage only, logs to stderr, and starts no
  web server. Set `AGENT_MODE=acp` instead of the flag if the editor cannot
  pass arguments.

## Act as the signed-in user

`agent.tools.cistern.credential-mode` (`service` | `per-user` | `forward`)
decides whose credential the `pod` tool presents to Cistern. `forward` sends
the bearer the caller authenticated with, never a substitute. The OpenAI
provider accepts per-user keys (`agent.credentials.per-user.openai.<userId>`),
and every outbound Cistern and OpenAI call carries the request's
`X-Request-Id`. Details in the README under "Acting as the signed-in user".
