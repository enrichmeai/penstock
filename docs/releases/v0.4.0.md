## Penstock remembers what you built, in a memory you own

With memory enabled (`AGENT_MEMORY_ENABLED=true`), Penstock recalls your own experience in
every turn: facts, the latest episodes of the project you are in, and matching patterns, loaded
into the system prompt before the first model call. Every card it loads is recorded in the audit
log. The memory is plain files in an open, versioned format, in a folder or a private git
repository you own, and the format does not depend on one model.

### Security fix: upgrade (affected: v0.1.0–v0.3.0)

From v0.1.0 through v0.3.0, the `pod` tool and the `jira_search` tool also sent the active LLM
provider's request headers: with Anthropic, the API key (`x-api-key`); with Copilot, its token and
headers. One shared HTTP client builder carried the provider's defaults into every client built
after it (#103). v0.4.0 gives every client only its own headers, and a test pins it for the pod
and for Jira.

- If you ran Penstock with the Jira tool configured, treat the key of the provider you ran as
  exposed to that Jira server and rotate it.
- A Cistern pod on your own machine is lower risk; rotate if its host, proxies or logs are not
  fully trusted.

### Your memory, outside this repository

```bash
export MEMORY_ROOT=/path/to/your/memory     # or --root on each script
AGENT_MEMORY_ENABLED=true AGENT_MEMORY_ROOT=$MEMORY_ROOT java -jar penstock-0.4.0.jar
```

- **One root, sections by project** (#101): `estate/` for what holds everywhere, and
  `projects/<name>/` per project. A session loads the estate and its own project, never another
  project's cards. `scripts/check-cards.sh --root` fails a fact filed under the wrong project.
- **Write into it** (#104): `write-episode.sh --root` drafts a dated record of the work as a
  file; `consolidate.sh --root --write` writes proposed facts from it into the same section's
  `facts/`. Both are files for you to review and commit; nothing is promoted further on its own.
  A line matching a credential shape stops the run before anything is written (a pattern check,
  not a guarantee).
- **Mirror it to a Cistern pod** (#102): `memory-publish.sh --root`; `memory-grant.sh reviewer
  --project <name>` lets a reviewer read one project's patterns, and write only to their own
  verdicts folder.
- **See what reached the model** (#105): the web UI's Audit view lists every fact, episode and
  pattern loaded into the turn, then the model call.
- **The format** (#99): every card carries `format: 1` and a `visibility`; JSON Schemas live in
  `schema/`, and nothing in the format depends on one model.

Checked before release against a Cistern pod with the Claude, Copilot and Ollama provider
settings, using a local stand-in that speaks each provider's API in place of the real services (no
real model answered): the stand-in recorded that each provider's request carried the recalled
cards, a session in another project loaded none of them, and a logging proxy saw no model
credentials reach the pod.

### What it does not do yet

- No automatic fallback: you choose one provider with `AGENT_LLM_PROVIDER` (default `copilot`);
  falling back to local Ollama when no key is set is #106.
- No memory browser or review inbox in the web UI yet (#107, #108); review happens in the files.
- Hosted sessions and Claude Cowork cannot read the memory yet: that path runs through the pod's
  MCP endpoint (#89, enrichmeai/cistern#220 and #118).
- `promote-pattern.sh` still writes into this repository, not a memory root.

### Breaking changes

- A card in this repository whose `visibility` is narrower than `memory.yaml`'s (for example a
  `private` card here) now fails `scripts/check-cards.sh` (#100): it belongs in your private
  memory root. No other breaking changes.
